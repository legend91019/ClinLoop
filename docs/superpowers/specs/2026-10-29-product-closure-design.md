# ClinLoop 本地产品收口设计

状态：用户于 2026-10-29 确认。范围仅覆盖本地产品流程；可观测性、云服务器部署和在线演示由队友负责。

## 目标

从新克隆的仓库开始，用一套命令准备合成患者，打开患者列表，完成“查房记录 → 医生签署 → Agent 候选 → 医生确认 → 合成检验到达 → 核对并闭环 → 交班”。

## 设计

- 根路径默认打开患者列表；带 `patient` 和 `view` 的深链接继续按原链接打开。
- 新增统一的本地初始化命令，复用现有 P-1001 旧演示和 P-2001～P-2006 工作台数据初始化，不清空已有数据库；运行两次保持幂等，ID 冲突明确失败。
- README 的主快速启动只介绍患者工作台，旧 P-1001 事件链标为高级演示。启动命令固定使用同一个数据库与 API 端口。
- 文书撰写页面明确标识 DeepSeek 实际调用、本地模板和未配置状态；任务分析的 mock 与真实 provider 不混称。
- 保持医生审核与来源约束，不新增诊断、医嘱、生产身份能力。

## 验收

1. 默认访问 `/` 可看到患者列表，不需要猜患者 ID。
2. 统一初始化连续运行两次，不重复创建患者、文书和任务。
3. 无 API Key 可选本地模板与 mock，完整验证产品操作；配置真实 provider 时明确显示真实调用状态，失败不伪装成功。
4. 后端、前端测试与构建通过；本地验收文档能复现主流程。

## 边界

本轮不改 AgentArts 云端编排、日志与监控方案、云部署。合成病例功能验收不能当作临床有效性或 95% 召回证明。
