# Workflow Agent 证据闭环改进设计

日期：2026-10-07。基于已确认的优先级，目标是让竞赛 MVP 的 Agent 轨迹对应真实取证动作，并避免无依据的缺口告警。

## 运行边界

DeepSeek 输出候选意图和只读工具选择。工具名必须是已注册的 MCP 只读工具；Worker 通过执行策略限制数量与超时，记录调用、结果引用和安全错误码。模型没有写入权限。确定性验证器依据同一患者、就诊、任务关联和事件可见时间判定缺口；信息不足时保留任务，不生成 Finding。

NOTE 创建候选 Intent/Loop。LAB 先关联唯一且等待该结果的 Loop，再检查检验和病程记录；在触发时点已经存在针对该结果的明确医生确认时不报警。不同任务的检验不得唤醒该 Loop。PROGRESS_NOTE 的显式 `acknowledges_event_id` 关联结果并推动重新规划候选，所有正式状态变化继续经 Guard/医生审核。每个 Finding 包含被查证据来源。

## 事件可靠性

API 采用数据库中的待发布事件记录来解决“数据库已提交、Redis 未收到”的窗口。Worker 可重领 Redis pending 消息；数据库提交后才 ack，处理过程以 event_id 幂等。模型错误会保留安全错误码并 ack；持久化异常不 ack。

## 可见性和验证

医生工作台能按患者查看 Agent 运行，包括无 Loop 的模型错误，提供合成事件入口以完成试用。真实 DeepSeek 调用只在本地显式配置 Key 后执行；自动测试使用本地假服务。离线评测应反映新的运行时逻辑并清楚标明没有真实模型调用。以通过完整发布门禁和一条可复现的合成端到端轨迹验收，不据此宣称临床效率改善。
