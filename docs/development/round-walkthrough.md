# 一次查房的演示与验收

初始化：`python -m scripts.init_round_walkthrough`。脚本只新增一位明确标识的虚构患者，重复执行保留所有审核和任务进度；标识冲突时拒绝操作。该病例的缺陷草稿由人工预置，用于核查验证，界面明确显示演示来源。

打开 `http://127.0.0.1:5173/?patient=P-ROUND-DEMO&view=records`，填写医生身份。

## 演示步骤

1. **查房前**：等待或发起准备分析。预期识别上次查房之后新增的血常规报告，提示血培养仍待回报、过敏史需核实。展开来源，确认是当前患者的报告。
2. **查房中**：点击“开始本次查房”。可录音或粘贴以下虚构对话，再保存并等待真实模型生成病历。生成后自动进入查房后；若当前有未保存修改，先保存，再打开新草稿。

   患者：今天感觉比昨天好一些。
   医生：请再确认一下过敏史。
   患者：我记不清了，需要问家属。
   医生：血培养结果出来后查看，处理完血培养结果后整理交接事项。

3. **查房后核查**：为稳定展示缺陷检测，选择“待审核查房草稿（故意遗漏交接安排）”。预期指出遗漏“处理后整理交接”的安排，并给出原始对话；不能把患者自述好转仅因缺乏客观指标判成错误，也不能把不清楚的过敏史写成“无过敏”。这一步与真实模型新生成草稿分开，不伪称生成器必然遗漏。
4. 补充诊疗计划为“血培养结果出来后查看；处理完血培养结果后整理交接事项。”保存后重新核查，再签署。旧核查须标记过期。
5. 签署后在同页的条件计划点击“开始分析”。核对“查看血培养结果”等待血培养、“整理交接事项”依赖前一任务。若 Agent 请求澄清，填写“交接事项指汇总本次未完成工作；查看并处理血培养结果后再整理，无额外时限”，重新分析或由医生明确调整条件，填写说明确认。
6. 在患者概况进入 Agent 任务中心，展开已有的模拟检验入口，发送一条血培养结果。返回查房后计划：第一任务应变为可处理，第二任务仍等待。医生核对结果并填写处理意见完成第一任务后，第二任务才能解锁。
7. 补充异常演示：取消前置任务不应解锁后续任务；修改依赖需填写原因；刷新页面仍保留进度和变更历史。

## 小样本验收

每个样例至少执行一次，记录实际输出和耗时；模型没有发现预期问题时如实记失败，不用人工预置输出替代。

| 样例 | 标准答案 | 重点指标 |
| --- | --- | --- |
| 新结果 | 准备单包含新血常规；血培养未出 | 关键变化召回率 |
| 缺陷草稿 | 原话有交接安排，草稿没有，应指出遗漏 | 遗漏检出率、来源正确率 |
| 患者自述 | “患者诉好转”保留为自述，无需额外客观证据才能记录 | 核查误报率 |
| 不确定信息 | 过敏史不明，不应写成无过敏 | 不确定性保留率 |
| 条件链 | 血培养到达→医生处理→交接任务解锁 | 依赖关系正确率 |
| 取消与变更 | 取消不算完成，调整留痕 | 状态转换正确率 |

指标统计：召回率=命中的预期项/预期项总数；核查精确率=医生确认有效的提示/全部提示；依赖正确率=正确依赖关系/预期依赖关系。空分母记“无样本”。另外记录每阶段从点击到结果的秒数、从准备到签署的点击数、人工修改次数和失败重试次数。

基线与新版使用相同病例、相同输入及相同模型各跑一遍后比较；尚未采集的数据不要宣称提效百分比。建议优先修复误报和阻塞，再优化耗时和点击次数。
