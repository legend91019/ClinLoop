# 患者 Agent 增强：准备、核查、条件计划

本次在现有患者工作台增加三项能力，独立调用本地配置的 DeepSeek 服务。原有 `AGENT_PROVIDER=mock` 不会将这些新能力降级为模板；没有密钥或模型失败时明确返回失败。

## 使用

- 进入「病历与查房」，填写医生身份后首次自动准备查房资料。阅读新增变化、未完成事项及核实问题；来源可展开查看。已有报告不会重复收费生成，资料变化后点击重新分析。
- 打开已保存病历，首次自动进行质量核查；未保存修改会阻止发起和审核。修改并保存后重新核查，旧报告标记过期，审核意见按报告版本保留。核查覆盖原始对话、检查及历史文书；缺少原始对话时不能核实口述遗漏。
- 在「Agent 任务中心」的「条件任务计划」选择已签署病历。Agent 提出任务、原文依据、前置关系、结果等待条件及澄清问题。医生补充说明后可重新分析，也可明确调整时间和条件。填写原因并确认后创建医生待办。
- 计划自动轮询依赖、同次就诊匹配检验及截止时间。结果到达仅将任务标记可处理；医生填写处理意见才会完成。取消前置任务不会解锁后续任务；修改依赖需医生记录变更原因。多份匹配报告需要医生核实，不自动选一份。

## 实现与范围

`care_assistance` 持久保存请求、结果、依据快照、实际工具调用、医生审核、计划绑定和变更历史。Worker 使用短事务领取任务，模型执行期间不持有写锁；超时或重启遗留运行会明确失败，允许重新发起。

模型通过受限 JSON 协议选择 `read_documents`、`read_labs`、`read_tasks`，工具结果固定限定患者和本次就诊。最多六轮，三个来源都需读取。最终输出经严格契约校验；引用必须存在，任务引用必须逐字出现在已签署目标文书（规范生成文书限定诊疗计划），依赖图必须无环。输入文本作为数据处理，不授予任意工具或医嘱写入权限。

证据范围：最近50份文书、50条检验和100项任务，超出时显式标识读取范围限制。每份报告记录资料指纹，资料变化后禁止确认旧计划或审核旧核查。临床语义仍需医生审核，来源校验不等同于内容正确性保证。

条件执行首版支持任务依赖、四类检查结果到达、截止时间和人工澄清。复杂数值/诊疗条件转换为澄清问题。检查匹配限定本次就诊及目标文书签署之后的报告时间。已有相似任务提示核实，完全同名活动任务禁止重复创建；暂不自动合并或取消旧任务。

患者页面查询不修改状态；后台在 Worker 每轮轮询更新已确认计划。已有手动任务接口同样执行条件检查，不能绕过依赖完成任务。计划调整和医生审核使用版本检查，后台更新也比较版本避免覆盖医生变更。

## 部署

生产数据库执行 `python -m alembic upgrade head`，新增迁移 `0004`。本地 SQLite 启动脚本会创建新增表并保留现有资料。重启 API 和 Worker，前端重新构建。密钥沿用 `DEEPSEEK_API_KEY`，模型和端点沿用 `DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`。不需要新增密钥或 AgentArts 资源。

测试覆盖患者隔离、来源伪造、越权工具、依赖循环、病历版本过期、无密钥失败、重复请求、结果等待、跨患者结果不唤醒、多结果歧义、取消阻塞、调整审计、旧版本冲突和运行中断恢复。
