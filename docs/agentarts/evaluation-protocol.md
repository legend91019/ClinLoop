# AgentArts 效果与效率评测协议

## 当前可复现的工程基线

运行 `python -m eval.run_online_eval --provider rules --corpus contest-v1`。冻结的 `contest-v1` 有 50 个合成病例：25 个应报告、25 个不应报告；标签与模型输入分离。当前规则基线为 TP 19、FN 6、FP 0、TN 25；召回率 19/25 = 76%，精确率 19/19 = 100%，阴性误报率 0/25 = 0%。这是合成单场景工程结果，不是临床效能。

确定性 MOCK 在同集上 TP 25、FN 0、FP 12、TN 13；100% 召回伴随 48% 阴性误报。MOCK 不是 LLM，也不是 AgentArts 结果，不能用于参赛的 Agent 效果结论。

## 预注册的真实平台检验

1. 先固定工作流版本、知识库版本、模型、提示词和 `contest-v1` 数据。运行一次 `rules` 与一次 `agentarts`，报告完整 50 例；禁止删除失败案例、重试后挑选最好成绩或把开发样本混入分母。
2. 命令：`python -m eval.run_online_eval --provider agentarts --corpus contest-v1 --output artifacts/eval/agentarts-online-local.json`。从环境变量读取 `AGENTARTS_ENDPOINT`、`AGENTARTS_RUNTIME_NAME`、`AGENTARTS_API_KEY`。报告不写密钥、提示词或原始响应。
3. 首要指标：召回率 `TP/(TP+FN)`，目标至少 95%；同时要求精确率至少 90%、阴性误报率不超过 10%、所有提示证据来源有效率 100%、模型错误计入漏报。50 例中有 25 个阳性，因此召回率达标至少需要 `TP=24/25`；25 个阴性中误报不得超过 2 例。目标为预设门槛，不是现有成绩。
4. 报出分子/分母、每例结果、模型错误数、工具调用数、平均模型耗时，并按 `followup`、`other_lab`、`unrelated_note`、`no_note` 分组。相同模板变体并非独立真实病例，统计置信区间不能代表临床总体。
5. 若低于门槛，记录失败案例 ID，回到开发集修改工作流，再冻结新版本与新的未见测试集；旧测试集不可反复用于调参。

## 实际节时实验

邀请至少 6 名具备病例工作流经验的参与者，使用完全合成的病例，随机平衡“纯人工查看”和“ClinLoop 辅助查看”的先后顺序。每人两种方式完成同等难度的 10 个病例：找出需跟进的检验结果、核验证据、决定是否接受提醒。记录每例开始与完成时间、遗漏、错误接受、主观负担。分析配对的中位耗时和差值，列出全部参与者、任务和异常；如样本很小，只作可用性探索，不宣称临床推广效果。不得虚构参与者或计时数据。

原始计时记录模板见 [human-study-template.csv](human-study-template.csv)。`participant_id` 应使用匿名代号，`mode` 取 `manual` 或 `clinloop`，每名参与者的两种模式任务应采用不同但配平的合成病例。完成后另存原始记录及分析脚本，保留失败和超时样本。

填好真实观察数据后执行：`python -m eval.run_human_study --input <私有原始CSV路径> --output artifacts/eval/human-study-local.json`。分析器要求同一参与者与 `task_id` 有完整的两种模式配对，核对时间戳与耗时，输出配对中位节省秒数、相对节省比例、识别正确率、证据核对正确率和错误接受率；报告只含汇总与输入 SHA-256，不含参与者代号或备注。原始 CSV 与报告默认不纳入 Git。
